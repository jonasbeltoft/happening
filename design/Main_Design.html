6a Happening v5 — Chalk & Ember

Same eight screens, same information, nothing else carried over. Chalk-white paper on warm grey, graphite ink, one ember accent, sentence case, 14–34px radii and soft cast shadows instead of hard offsets. Below: what each screen actually has to say, then the screens.

Ember is for one thing per view: the decision the user hasn't made. Graphite is ink and the splash background. Never ember-on-graphite with an ember glow — that reads neon; on dark, the primary button is chalk with an ember underline.
Graphite as contrast
Roughly one graphite surface per screen, and only where the content deserves emphasis over its neighbours — the friends-are-going card on Explore, Accept on an invite, the whole splash. Chalk text, ember reserved for the eyebrow or a single number. Two black cards in one view flattens the effect; a black card next to an ember button makes both shout.
Type
Instrument Serif
Screen titles 30–32 · section heads 21 · numerals 19–30. Italic for the wordmark and pitch quotes.
Archivo
Everything else. Row titles 15/600 · body 13.5/400 · meta 12.5/500 · eyebrows 10.5/700 uppercase, .14em tracking.
Sentence case everywhere except eyebrows. Numbers set in the serif when they're the point (counts, walk minutes, dates); in Archivo when they sit inside a sentence.
Shape & elevation
Radii: 10 pills/tiles, 12–14 buttons and small tiles, 16 rows, 18–20 cards, 26–28 sheets, 34 device frame. Three elevations only — rows (1px hairline shadow), cards (short 6/14), hero cards and sheets (14/30). Shadows are short and vertical; if one reaches further than the element is tall, it's wrong. Any clipped scroll row needs padding-bottom for its own shadow.

Only unmade decisions get button chrome. A settled state is flat text with a check — never a pill that looks pressable. The meta line carries "no answer yet" in ember ink so the row explains itself without a label. Same vocabulary on Mine, the map drawer and event pages.
Action bars & buttons
Secondary
sub-label
Primary!
consequence of tapping
Every commit bar is the same: fixed 56px buttons, 10px gap, 14/22/26 padding, hairline top border. Primary sits on the right — that's where the thumb is. Two-line buttons are deliberate: bold verb over a quiet consequence ("you'll be number 65", "Tap to change"). Destructive or declining choices stay grey and slimmer (104px) than the thing you want tapped.
Horizontal shelves
Anything with more items than fit scrolls sideways and bleeds off the right edge (negative margin past the 22px gutter) — never a "+2" stub. Native scrollbars are always off (scrollbar-width:none); the affordance is a 56×3 track under the shelf whose thumb follows real scroll position and can't be dragged.
Event page stack
1 · Identity — eyebrow, title, venue, avatar stack with friend count, Invite
2 · Facts — labelled tiles or rows, each with an inline icon
3 · Pitch — one italic serif line from the organizer
4 · Map — strip with walk time
5 · Description — the long version, with More
6 · Feed — composer first, then posts, last one with a photo
Every event page uses this order whether or not it has a cover. Facts appear once: address lives in the facts, walk time on the map, attendance in the avatar row. The commit bar is pinned; everything above it scrolls, ending in a 24px spacer.
Rules & gotchas
Icons are inline SVG on currentColor — never icon fonts or private-use glyphs, which render as empty boxes off-device.
No em dashes, no prime marks for minutes ("14" over "min", not 14′), no emoji.
Every count states its unit in words; two numbers in one line must mean the same kind of thing.
Scroll columns are flex:1;min-height:0;overflow-y:auto — a fixed-height column silently clips its last row.
Pinned headers over scrolling content need their own chalk background, or the title collides with the bar.
Hit targets 44px minimum; row buttons 36–40px tall with a nowrap meta line so nothing wraps into them.
The information, screen by screen
01 · Splash
Wordmark, promise line, a live list of what's on right now (3 named events with time or “now”, plus “+28 more”), tonight's event count and people-out count, and four ways in: see what's happening, log in, join with a code, browse anonymously.
02 · Mine
Your week and RSVP tallies (going / interested / tonight); pending invites with inviter, time, going-count, accept or later; the next thing you're going to with countdown, walk, price, attendance, friends; later-this-week rows with day, time, distance and their own RSVP state; upcoming vs previous; search and code entry.
03 · Map
City selector, tonight's count and people out, pins including one cluster and one event you're already going to, filters (now, under 1 km, free, friends), recenter, and an “around you now” drawer: nearest events with distance, start or since-time, attendance, friends, one-tap RSVP.
04 · Explore
Search for events or places, code entry, and shelves that state their own reason — “because you went to 3 markets”, “10 friends are going” with named friends — plus a walkable-in-the-next-hour list of 7, each row carrying distance, start time and walk time.
05 · Event, with cover
Back and share, organizer cover, live state, city, title and venue, attendance including how many are friends, the facts (when, price, where, walk, vibe), a two-line description with more, a map strip with walk time, friends going with an invite action, and a commit bar: interested, or I'm going.
06 · Event, no cover, answered
The same page without imagery: event code in the bar, label/value rows for when, where, price, vibe, host and their event count, attendance; the organizer's one-line pitch as a quote; map with walk time; and the state flipped — you're going, tap to change, with invite the only thing still asking.
07 · City page, logged out
Wordmark and “right now in your city”, tonight's count and people out, three live rows with state or start time, “+28 more — sign in to filter”, a map preview, the rule stated plainly (browsing is free; saving, RSVP and invites need an account), then create account and log in.
08 · Join by code
A sheet over the current screen: close and paste-link-instead, six character cells (three filled, one focused), the rule that private events never appear in search, and once the code resolves, a preview showing title, private, day, time and total going only — never which friends.
